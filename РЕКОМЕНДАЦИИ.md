# Рекомендации по развитию портала

Список предложений на будущее. Это **только идеи** — что из них внедрять,
решаете вы. Разбито на функциональные, технические и визуальные (UX).
Отмечены пункты, вытекающие из текущих доработок.

## Функциональные

1. **Пароли Humax (`/hupass`)** — метод в API есть, но набор обязательных
   параметров запроса по ответам сервиса восстановить не удалось (всегда
   «Отсутствуют обязательные параметры запроса»). Нужен точный контракт от
   команды DRIVEMODS: имена полей запроса и форма успешного ответа. После
   этого добавим кнопку «+ Пароль», хранение записей паролей и вывод их в
   ленте (как на присланном скрине).
2. **Фискальный чек возврата (54‑ФЗ).** Сейчас возврат средств только меняет
   статус платежа на «Возвращён». Стоит отправлять в АТОЛ чек «Возврат
   прихода» и хранить его так же, как чек прихода.
3. **Отзыв заявки на аннулирование дилером.** Дать представителю возможность
   отменить свою заявку, пока она «на рассмотрении».
4. **Уникальный индекс на активную заявку.** Частичный `unique` в БД
   (`licenseId` где `status = PENDING`) полностью исключит гонку при двойном
   клике — сейчас защита на уровне UI и проверки в роуте.
5. **Telegram‑уведомления.** `sendTelegram` — заглушка. Реализовать доставку
   через Bot API (токен и chat_id уже предусмотрены в настройках).
6. **Действия из карточки лицензии.** Продление, восстановление, повторная
   выдача и возврат средств прямо из карточки, а не только через отдельные
   разделы.
7. **Массовые операции** в таблицах лицензий и платежей: множественный выбор,
   пакетное аннулирование, экспорт выбранного.
8. **Сохранённые фильтры.** Модель `SavedFilter` есть в схеме — довести до
   рабочего UI (быстрые пресеты в списках лицензий/платежей).
9. **Редактируемые шаблоны писем.** Модель `EmailTemplate` есть — перевести
   уведомления (аннулирование, оплата, возврат) на шаблоны из админки.
10. **Двухфакторная аутентификация.** Инфраструктура (otplib, поля в `User`)
    заложена — включить TOTP хотя бы для администраторов.
11. **История генераций на карточке.** Сохранять `first_gen`/`last_gen` из
    DRIVEMODS в лицензии при выдаче, чтобы видеть их и после выдачи, а не
    только на шаге проверки.
12. **Частичный возврат** и привязка возврата к конкретной аннулированной
    лицензии одним действием.

## Технические

1. **CI/CD.** GitHub Actions: линт + `tsc` + сборка + прогон `test:*` на PR;
   автодеплой на ВМ по пушу в `main` вместо ручного `deploy/update.sh`.
2. **Автотесты.** Существующие `scripts/test-*.ts` — ручные. Добавить
   unit‑тесты (Vitest) на критичную логику (цены, лимиты, статусы) и гонять
   e2e в CI.
3. **Мониторинг ошибок.** Подключить Sentry (или аналог) и структурный лог
   (pino уже в зависимостях) во всех роутах.
4. **Резервные копии БД.** Автоматический дамп PostgreSQL по расписанию +
   регулярная проверка восстановления.
5. **Секреты.** Перевыпустить утёкший приватный TLS‑ключ, вынести секреты из
   `.env` в менеджер секретов; не хранить ключи в репозитории.
6. **Rate limiting** на публичных и auth‑эндпоинтах (защита от перебора и
   спама заявок).
7. **Устойчивость к DRIVEMODS.** Ретраи с бэкоффом на сетевые сбои (сейчас
   один таймаут), единая точка маппинга полей API.
8. **Сборка.** Рассмотреть `output: "standalone"` (меньше и быстрее деплой)
   или контейнеризацию; вынести Framer Motion из критического пути ради TTI.
9. **БД‑производительность.** Ревизия N+1 (повторные запросы `me`), точечные
   `groupBy`‑агрегации для дашбордов вместо выборок целиком.
10. **Оркестрация файлов S3.** Отдельная задача чистки «осиротевших» объектов
    (device_id.bin/лицензии без записей в БД).
11. **Заголовок сборки/версии.** Показывать версию/commit в футере админки для
    диагностики после деплоя.

## Визуальные (UX)

1. **Мобильные таблицы.** Списки лицензий и платежей на телефоне уезжают в
   горизонтальный скролл (`min-w`). Дать карточное представление на узких
   экранах.
2. **Скелетоны и пустые состояния** единообразно во всех списках и на
   дашбордах (сейчас где-то «Загрузка…», где-то ничего).
3. **Тёмная тема.** Иконки солнца/луны уже лежат в `/public` — реализовать
   переключатель темы.
4. **Доступность (a11y).** Контраст тегов‑статусов, видимые фокус‑состояния,
   `aria`‑подписи у иконочных кнопок.
5. **Признак «заявка на аннулирование»** дублировать на дашборде дилера, а не
   только в списке лицензий.
6. **Фавиконки и превью.** Добавить размеры 16/32 и apple‑touch 180×180
   (сейчас `.ico` + один PNG 169×169), а также OG‑картинку для ссылок.
7. **Единые состояния кнопок** (loading/disabled) и inline‑валидация форм
   вместо только тостов.
8. **Подсказки по датам генерации** в карточке лицензии (первая/последняя
   генерация из DRIVEMODS) наглядным блоком.
